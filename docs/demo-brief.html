The one idea the judges must leave with

The 1930 helpline can freeze a bank account. It goes blind the second the money becomes crypto. In our case that happens 58 seconds after the debit. Violet Milk starts exactly there and ends with a court-ready dossier and the name of the exchange to serve notice on.

Everything else in this brief supports that sentence. If you have thirty seconds, say that sentence.

Before the judges arrive

Pre-flight, in this order

  1. Set stage mode in .env

    LIVE_CACHE_FIRST=true — pre-tested mainnet addresses then replay from disk in ~0.35s instead of gambling on venue wifi. The UI still shows EtherscanSource (cached), so you are not claiming a live pull.

  2. Warm the caches

    prewarm_ai.py then pretest_live.py. Both with .venv\Scripts\python.exe, never bare python.

  3. Build the frontend and start one server

    npm run build, then uvicorn on port 8000. One process, one port — nothing else to go wrong.

  4. Log in and run the demo trace once

    Leave the app sitting on the Command Center with the case already worked. Never open on an empty shell.

  5. Unplug the wifi and run it again

    The last rehearsal must be the offline one. If it survives that, nothing at the venue can hurt you.

Do not demo the Tornado 0.1 ETH pool. It takes 4.1s even cached because depth-2 keeps discovering new addresses. Use the Tornado Cash Router — 0.35s, 18 entities, and it is an OFAC-designated address, which is a stronger story anyway.

Condition 5 · what a legal advisor will ask

Legal questions

Is anything this produces admissible in an Indian court?

The dossier is formatted to support a Section 63 BSA certificate. It does not create one.

Section 63 of the Bharatiya Sakshya Adhiniyam 2023 requires a certificate describing how the electronic record was produced and by what device or process. Our dossier sets out exactly that: which rules ran, on which inputs, with what version, and the SHA-256 of the output. A human being still signs the certificate. Software cannot attest to its own output and we do not pretend it can. Our statutory wording has not yet been reviewed by counsel, and that is written into the README and the dossier itself.

How do you prove the evidence was not altered after collection?

Every action is written to an append-only log where each entry hashes the one before it, and /audit/verify names the first broken link. The document's own SHA-256 is recorded in that log — a document cannot contain its own digest, so a detached record is the only way to verify it later. Optionally the digest is anchored on a public blockchain.

State the limit before they find it: this makes tampering detectable, not impossible. Anyone who can rewrite the whole chain from the point of edit forward can hide a change. Anchoring is what closes that, because the anchor is outside our control.

The system uses AI. Does that not make the evidence unexplainable?

That is precisely why the AI cannot touch the score.

A neural network cannot be cross-examined. So every number that could matter to a court comes from seven fixed rules with cited evidence and arithmetic that reconciles. The language model drafts narrative prose and suggests CSV column mappings; the anomaly model produces investigative leads on a separate endpoint. Neither can move a score, and a test proves it by showing the model flags the complainant — who scores zero.

Can this identify an accused person?

No, and the STR draft says NOT IDENTIFIED in those words. We trace flow, not identity. A wallet address is not a person. Identity comes from the exchange's KYC records, obtained under Section 94 BNSS. What we produce is the thing that makes that notice writable — which exchange, which deposit address, which amount, which timestamp.

What is the exposure if a risk score is wrong and someone is wrongly suspected?

The dossier states in terms that a score is an investigative prioritisation and not a finding of guilt. The rule weights are documented as reasoned but uncalibrated — we say so rather than implying a validated model. Because the arithmetic is transparent, a wrong score is arguable: an accused can point at rule R4 and contest the bridge inference. An opaque score would be far more dangerous, because it could not be challenged at all.

Can you file the Suspicious Transaction Report?

No. FIU-IND has no public submission API and filing requires registered Reporting Entity status. We produce a draft in the correct shape, with the reporting-entity fields left as TO BE COMPLETED. A test walks the API schema and fails the build if any endpoint ever appears that could transmit a report. That restriction is enforced in code, not in a promise.

What about data protection — the DPDP Act?

Today the system runs on synthetic data, and the only external transmission is case facts sent to a language model to draft narrative prose. For a real deployment that decision has to be made deliberately: the template path already exists, is tested, and produces a complete dossier with the AI switched off entirely. We flag this as an open item rather than claiming compliance we have not earned.

Condition 5 · what a police officer will ask

Operational questions

1930 and CFCFRMS already freeze accounts. Why do I need this?

Because they work on bank rails, and this case leaves bank rails in 58 seconds.

CFCFRMS is genuinely good at what it does — golden-hour freezing across banks using UTRs. It has no visibility once funds are converted to crypto at an exchange. We do not replace it. We take over at the exact point it stops, and we tell you which exchange received the money and which deposit address to name in your notice.

Can I freeze crypto with this?

No. Freezing requires the exchange to act. What this gives you is a better freeze request: a named deposit address, an amount, a timestamp, and an illicit-share figure — instead of a request that says "please check for suspicious activity."

Do my officers need to understand cryptocurrency?

They need to paste an address and read a score with reasons written in English underneath it. The seven rules are stated as sentences — "funds moved out three minutes after arriving", "a mixer was used". No officer needs to know what a mixer is technically to understand that using one is a deliberate act of concealment.

What do I actually do with the output on Monday morning?

Three things. Attach the dilution figure to a freeze request. Serve a Section 94 BNSS notice on the exchange named in the trace, citing the deposit address. File the dossier with the case papers under a signed Section 63 certificate. The STR draft goes to whoever in your chain deals with FIU-IND.

How long does it take?

The trace and the dossier are minutes. The honest comparison is not against a faster tool — it is against the current position, where a district cyber cell has no practical way to follow funds past the exchange boundary at all.

The internet at my station is unreliable.

It runs offline. Pre-test the addresses you care about and it replays from disk; with the network entirely dead a circuit breaker trips after three failures and serves cache in about a second. We rehearse the demo with the wifi unplugged for exactly this reason.

What if the exchange is foreign and ignores the notice?

Then you have a documented trail ending at a named foreign entity, which is the basis for an MLAT request or an FIU-IND referral — and it is a great deal more than an unanswered question. We do not claim to solve international cooperation. We claim to produce the document that cooperation requires.

Why does the mule bank account only score 15?

Because the score answers a different question — and the panel already shows the right one.

The score measures depth in the laundering machinery: mixers, bridges, fan-out, structuring. A mule account does one thing, receive and forward, so only the rapid-dispersal rule fires. For that account the number that matters is on the same screen — ILLICIT 100%. Every rupee through it traces to the complainant, and that is what goes on the freeze request. The score exists for the unlabelled hex addresses where you have nothing else to go on.

If asked what was hard

Problems we hit building it

Specific engineering answers land far better than "time management". Pick two.

  • Ranking mixed assets is meaningless. Sorting transfers by raw amount put 1,000 ETH above 47 USDT — different units entirely — and starved the USDT out of the graph completely. USDT is the asset Indian fraud actually uses, so we were dropping the evidence that mattered. Fixed by giving each asset its own share of the per-node budget.
  • Dilution returned 0.0 for every node in live mode. You cannot reconstruct a wallet's balance at the moment funds arrived from a public explorer. Rather than show a confidently wrong ratio we split it into two models, and the live one carries a caveat saying in plain words that it is not a dilution figure.
  • A forged USDT contract on Tron reported a 7.5-trillion transfer. Anyone can deploy a token called "USDT". We now verify tokens by contract address, never by ticker.
  • The column mapper read a date as money. A bank statement header Value Dt matched the amount rule's pattern for "value". A date column was being read as the transaction amount. There is now a regression test named after it.
  • A dead network took 62.7 seconds to fall through to cache. Correct results, useless on stage. A circuit breaker now trips after three failures and serves cache in about a second.
  • Today: the cache was a fallback, not a cache. On a working network every trace still paid full API latency. Slow venue wifi — not dead, just slow — was the one failure mode nothing detected. Fixed this morning.

If asked what comes next

What officialisation actually requires

Answer this as a person who has thought about deployment, not as someone listing features.

  1. Legal review of the statutory wording

    The Sec 63 BSA certificate and Sec 94 BNSS references are drafted in good faith and have not been checked by counsel. This is first because everything downstream depends on it.

  2. A CERT-In empanelled security audit

    Standard prerequisite for any system handling case data on government infrastructure.

  3. A DPDP Act decision on the AI narrative

    Either an in-house model, or ship with the tested template path and no external transmission at all.

  4. Integration with CCTNS and NCRP

    Read the FIR rather than retyping it. This is the difference between a tool an officer uses and a tool an officer is asked to also use.

  5. An attribution feed

    Our honest weak point. Realistically: an arrangement with FIU-IND-registered Indian exchanges, or a commercial licence layered underneath our workflow.

  6. Multi-user roles and real key management

    Today it is one seeded officer and a default password the app itself warns about. Production needs per-officer accounts and keys in an HSM.

  7. A three-month pilot in one cyber cell, then measure

    Cases where the trail continued past the bank boundary. If that number is not meaningfully above zero, the project has not earned wider deployment.

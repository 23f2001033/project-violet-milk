Where it stands

The build is finished and the demo runs unplugged

Every capability the deck claims is exercised by a test. The system traces a seed address across Ethereum and Tron, scores wallets against seven documented rules, computes proportional dilution, generates a Sec 63 BSA dossier and an FIU-IND STR draft, records every action in a hash-chained custody log, and can anchor a document digest on-chain. It serves as one process on one port.

It runs against three interchangeable data sources — a curated synthetic case, live Ethereum via Etherscan, live Tron — and no engine knows which one it is reading from. Live responses, AI narratives and anchor receipts are all cached to disk, so the entire demo works with the network cable pulled. That was tested, not assumed.

The rule everything else was built around

The AI never touches the score

Risk scores come from seven rules with fixed weights and cited evidence. Nothing statistical, learned, or generative can move a number a court might be asked to accept. The language model writes narrative prose and guesses at CSV column headings; the Isolation Forest and DBSCAN pass produces investigative leads on a separate endpoint with a separate shape. Neither can reach the score.

This is not a promise in a slide — it is enforced by a test, and the proof is embarrassing in the right way:

test_an_ml_outlier_is_not_automatically_high_risk

The anomaly model flags the complainant — they moved the largest single amount in the case, so they look statistically odd. The complainant's risk score is 0. If the model drove scoring, the victim would be the prime suspect. That test is the reason the model is kept off the score.

Six things that were wrong, and are not now

Each of these was a genuine defect found by attacking the build rather than demonstrating it. Each is now covered by a test that fails if it regresses.

Dilution was silently meaningless on live chainsClosed

BeforeEvery node returned 0.0 in live mode. Historical balances cannot be reconstructed from a public explorer, so the denominator was empty — and the UI showed the emptiness as a clean result.
NowTwo explicit models. haircut for curated evidence; propagation for live traces, which carries a caveat stating in plain words that it is not a dilution figure.

The custody log could be edited without a traceClosed

BeforeAn append-only table that anyone with the SQLite file could rewrite. The chain-of-custody claim was doing no work.
NowEach entry hashes its predecessor. /audit/verify names the first broken link. Rows order by an explicit seq, not rowid.

Uploaded evidence never reached the traceClosed

BeforeA CSV could be uploaded, parsed and stored, and then had no effect on the graph. The ingestion feature was a dead end.
NowRows merge into the case graph as typed nodes and edges. Bank statements and transfer lists are both handled; naive timestamps are read as IST, not UTC.

Anyone could write to the custody logClosed

BeforeThe officer's name was a form field. The log recorded whatever the request body claimed.
NowPBKDF2-HMAC-SHA256 at 240,000 iterations, HMAC-signed session tokens, and identity taken from the session — never from the payload.

Only one chain, and it was the wrong oneClosed

BeforeEthereum only. Indian cyber-fraud proceeds overwhelmingly move as USDT on Tron.
NowFull TRC-20 support. Tokens are verified by contract address, never ticker — a forged "USDT" contract was caught trying to report a 7.5-trillion transfer.

A document's integrity rested on our own databaseClosed

BeforeThe dossier hash was recorded in the same system that produced the dossier. Circular, and a defence lawyer would say so.
NowOptional on-chain anchoring of the digest, first-write-wins, recording block time, block number and sender. Receipts cached so the dossier can cite them offline.

Guarantees under test

What the 183 tests actually hold down

  • No endpoint can file an STR. A test walks the OpenAPI schema and fails if any mutating route ever appears under a path segment like file, submit or finnet. FIU-IND has no public submission API and we are not a Reporting Entity.
  • Every risk score reconciles to its indicators. Score equals the clamped sum of its cited rule points, or the test fails.
  • The whole flow survives the AI being gone. One test deletes the key and the cache, then generates a full dossier from the deterministic template and heuristic mapper.
  • The API still answers with the SPA mounted. FastAPI matches routes in registration order; a catch-all in the wrong place silently swallows /api/health.
  • The printed hash matches the file on disk. For both the dossier and the STR draft.
  • The private key never leaks. A test asserts the anchoring key appears in no receipt and no response.
  • A date column is never read as money. Regression test: the mapper once claimed Value Dt as the transaction amount.

Stated limits

What it does not claim

These are in the README, the dossier and the deck. Volunteering them is cheaper than being caught by a judge who asks.

  • The rule weights are not calibrated. Seven rules with defensible reasoning and no empirical basis for +20 versus +15. They are explainable, which is the point; they are not validated against outcomes.
  • Bank clocks and block clocks are not the same clock. Time-correlation inference across the two is a lead, not proof, and is drawn as a dashed edge for exactly that reason.
  • The narrative leaves the building. Case facts are sent to Groq to draft prose. Acceptable for synthetic data; a real deployment needs that decision made deliberately, or the template path used.
  • Anchoring proves a document existed by a certain time. It does not prove the document is true, and the dossier says so in those words.
  • The statutory wording is unreviewed. Sec 63 BSA 2023 and Sec 94 BNSS references are drafted in good faith and have not been checked by a lawyer.
  • It is not affiliated with Chandigarh Police. Stated in the README's first lines.

The deck

Rebuilt against the software, not the plan

Fifteen slides, validated and rendered through PowerPoint itself rather than a substitute renderer. Where a slide and the build disagreed, the slide was corrected — a competitor comparison table, an "OTC tracked 100%" figure and a Sec 63(4) tamper-proof claim were all removed because nothing in the code supports them.

  • A new chain of custody slide showing the before and after, and naming the limit out loud: tampering is made detectable, not impossible.
  • The pipeline's ingest step now describes real merging into the case graph.
  • Evidence figures refreshed: 2 chains, 7 rules, 60% → 12%, works unplugged, 183 tests across 19 endpoints.
  • The line count now cites 8,499 — a plain wc -l over backend/app and frontend/src, so a judge can reproduce it in one command. The previous figure no longer reconciled with anything.

If a judge hands over an address

The answer is to paste it in

That was the whole reason for the source abstraction. An Ethereum or Tron address typed into the seed field runs the same seven rules, the same bounded trace, the same custody log and the same dossier as the curated case — with propagation instead of dilution, and a caveat on screen saying why. If the venue's network fails, the three pre-cached addresses answer instantly.

The honest failure mode is worth rehearsing too: an address with no relevant activity returns a small graph and a low score. That is the system working. Say so rather than reaching for the demo case.
